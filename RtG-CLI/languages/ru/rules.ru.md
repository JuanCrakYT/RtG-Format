# Правила команд RtG-CLI

## 1. Общая структура

Команда RtG-CLI состоит из основной команды и, опционально, аргументов.
Общий формат:

`rtg <команда> [<аргументы>]`

Первый аргумент после `rtg` определяет, какая команда или аддон будет выполнена.

Примеры:

`rtg image`

`rtg preview`

`rtg help image`

---

## 2. Зарегистрированные команды

Основные команды должны быть зарегистрированы в конфигурации RtG-CLI.
Команда идентифицируется по её внутреннему ключу.

Пример:

`image`

Ключ `image` идентифицирует соответствующий аддон, независимо от имени, отображаемого пользователю.
Пример:

`image` → `RtG Image`

`preview` → `RtG Preview`

Отображаемое имя не должно использоваться как идентификатор команды.

---

## 3. Команды RtG-CLI и команды аддонов

RtG-CLI и аддоны могут иметь свои собственные команды и аргументы.

До идентификации аддона команды и аргументы принадлежат RtG-CLI.
После идентификации аддона префикс определяет, кому принадлежит каждый аргумент:

- Без дефиса (`-`) → принадлежит аддону.
- Два дефиса (`--`) → принадлежит аддону.
- Один дефис (`-`) → принадлежит RtG-CLI.

Пример:

`rtg image convert`

- `image` → аддон.
- `convert` → команда аддона.

Пример:

`rtg image --width 128`

- `image` → аддон.
- `--width` → аргумент аддона.
- `128` → значение аргумента аддона.

Пример:

`rtg image -lang`

- `image` → аддон.
- `-lang` → аргумент RtG-CLI.

---

## 4. Системные аргументы

До идентификации аддона RtG-CLI использует свои собственные правила синтаксиса.
Длинные системные опции используют два дефиса:

`rtg --version`
`rtg --help`

Системные аббревиатуры используют один дефис:

`rtg -v`
`rtg -h`
`rtg -l`

После идентификации аддона опция, начинающаяся с одного дефиса (`-`), принадлежит RtG-CLI.

Пример:

`rtg image -lang`
`rtg image -en`

---

## 5. Аргументы до и после аддона

Аргументы RtG-CLI могут иметь разное значение в зависимости от того, появляются они до или после идентификации аддона.

До идентификации аддона аргументы принадлежат RtG-CLI.

Например:

`rtg --lang`

Показывает доступные для RtG-CLI языки.

После идентификации аддона аргументы интерпретируются согласно правилам владения, установленным для аддонов.

Например:

`rtg image -lang`

Запрашивает доступные для аддона `image` языки.

Таким образом, позиция аргумента определяет его контекст и предотвращает путаницу между глобальными аргументами RtG-CLI и аргументами, используемыми после идентификации аддона.

---

## 6. Позиция системных аргументов

Системные аргументы не должны появляться перед командой или аддоном, на которые они влияют, когда аргумент зависит от этой команды.

Правильный пример:

`rtg help image -en`

Неправильный пример:

`rtg help -en image`

В этих двух примерах системная команда `help` использует эту структуру, поэтому второй пример неверен:
`help <target> <options>`

Позиция должна чётко определять, какая команда получает аргумент.

---

## 7. Команды и аргументы аддонов

Команды записываются как отдельные аргументы терминала.
Команда не должна содержать пробелов, если она не заключена в кавычки.

Следующие аргументы могут использоваться аддоном согласно его собственному интерфейсу.

Например:

`rtg image convert image`

может быть интерпретировано как:

- `image` → аддон
- `convert` → команда аддона
- `image` → аргумент команды

---

## 8. Использование дефисов в командах аддонов

После идентификации аддона:

- Аргументы без дефиса принадлежат аддону.
- Аргументы с двумя или более дефисами (`--`) принадлежат аддону.
- Аргументы с одним дефисом (`-`) принадлежат RtG-CLI.

Примеры:

`rtg image convert`
`convert` → аддон.

`rtg image --width 128`
`--width` → аддон.

`rtg image -lang`
`-lang` → RtG-CLI.

---

## 9. Интерфейс команд аддонов

Специфические команды аддона определяются самой программой аддона.
RtG-CLI использует конфигурацию аддона для поиска его интерфейса команд через свойство `program commands`.

Это свойство содержит пути к файлам, предоставляющим интерфейс команд программы.

Пример:

```json
"program commands": [
    "../tools/RtG Image/commands.py"
]
```

RtG-CLI может использовать этот интерфейс для обнаружения или выполнения доступных аддону команд, но не должен предполагать или менять значение его внутренних команд.

Аддон может определять дополнительные команды, не зарегистрированные напрямую как команды RtG-CLI.

Внутренняя реализация программы может отличаться между аддонами, если она предоставляет интерфейс, совместимый с правилами RtG-CLI.

---

## 10. Языки

Доступные для аддона языки определяются через его конфигурацию.

Пример:

`lang: ["es", "en"]`

Переведённые тексты идентифицируются с помощью соответствующего кода языка.

Пример:

`content.ru`
`content.en`

Селектор языка, используемый RtG-CLI, должен рассматриваться как системный аргумент.

Пример:

`rtg help image -en`

---

## 11. Язык по умолчанию

Если `-<язык>` не указан, RtG-CLI будет использовать первый язык, определённый в `rules`.
Если `-<язык>` указан, RtG-CLI будет использовать этот язык, если он доступен.

Первый язык, определённый в объекте `rules` файла `assets.json`, является языком по умолчанию для правил.

Когда пользователь запрашивает правила без указания языка, RtG-CLI должен использовать этот первый язык.

Например:

```json
"rules": {
    "es": "./rules.es.md",
    "en": "./rules.en.md"
}
```

В этом случае:

`rtg -r`
и
`rtg --rules`

отобразят правила на испанском, так как `es` — первый определённый язык.
Для запроса другого языка необходимо использовать соответствующий селектор:

`rtg -r -en`

Порядок языков внутри `rules` определяет только язык по умолчанию. Он не меняет доступные языки.

Это правило также применяется к другим селекторам языка, таким как:

`rtg help image -es`

---

## 12. Язык не меняет команду

Смена языка изменяет только текст, отображаемый RtG-CLI.
Она не меняет внутреннее имя команды.

Пример:

`rtg help image -es`

и

`rtg help image -en`

всё ещё ссылаются на одну и ту же команду:

`image`

---

## 13. Помощь

Общая помощь получается с помощью:

`rtg help`

Помощь для конкретной команды получается с помощью:

`rtg help <команда>`

Помощь может быть запрошена на конкретном языке:

`rtg help <команда> -<язык>`

Пример:

`rtg help image -en`

---

## 14. Запрос языков

Доступные для аддона языки можно запросить с помощью:

`rtg help <команда> -lang`

Пример:

`rtg help image -lang`

Эта опция принадлежит RtG-CLI, а не аддону.

---

## 15. Аддоны не должны менять системные правила

Аддон может определять свои собственные команды и аргументы, но не может переопределять значение аргументов, зарезервированных RtG-CLI.

Например, аддон не должен использовать `-h` для придания другому значению системной помощи.
Имена, зарезервированные RtG-CLI, имеют приоритет над командами аддонов.
Команды и опции, зарезервированные RtG-CLI, должны быть явно определены интерфейсом CLI.
Аддон не может переопределять поведение зарезервированной опции.

---

## 16. Разделение между идентификатором и именем

Внутренний ключ аддона используется для его идентификации.
Имя аддона используется только как описательная информация или для отображения пользователю.

Пример:

`image` → внутренний идентификатор

`RtG Image` → отображаемое имя

Не следует предполагать, что отображаемое имя может использоваться как команда.

---

## 17. Команды должны быть детерминированными

RtG-CLI должен уметь определять, принадлежит ли аргумент системе или аддону, не завися от описательного имени программы.

Интерпретация должна основываться на структуре и правилах команды.

Пример:

`rtg help image -en`

должен всегда интерпретироваться одинаково:

`rtg` → CLI

`help` → команда CLI

`image` → аддон

`-en` → опция CLI

---

## 18. Неизвестные аргументы

После идентификации аддона RtG-CLI должен определять владение каждым аргументом по его префиксу.

* Аргумент без дефиса принадлежит аддону.
* Аргумент с двумя или более дефисами (`--`) принадлежит аддону.
* Аргумент с одним дефисом (`-`) принадлежит RtG-CLI.

Если RtG-CLI получает неизвестный системный аргумент, он должен сообщать, что опция не существует.

Аргументы аддона должны передаваться аддону без попытки RtG-CLI интерпретировать их значение.

---

## 19. Не предполагать незарегистрированные команды

RtG-CLI не должен считать команду валидной только потому, что существует связанная папка, файл или программа.

Команда должна быть определена в соответствующей конфигурации.

---

## 20. Совместимость

Аддоны должны соблюдать правила синтаксиса RtG-CLI для корректной интеграции.
Аддон может иметь полностью другую внутреннюю реализацию, но его интерфейс команд должен следовать правилам, установленным RtG-CLI.

---

## 21. Правило приоритета

После идентификации аддона один дефис (`-`) зарезервирован для RtG-CLI.
Аддон не может использовать аргументы, начинающиеся с одного дефиса.
Аргументы, начинающиеся с двух или более дефисов (`--`), или не начинающиеся с дефиса, принадлежат аддону.

---

## 22. Аргументы аддона

После идентификации аддона RtG-CLI не должен предполагать значение аргументов, специфичных для аддона.

Аргументы, принадлежащие аддону, должны передаваться программе аддона для их обработки.

Пример:

`rtg image --width 128`

RtG-CLI идентифицирует `image` как аддон.

`--width 128` соответствует интерфейсу RtG Image и должен обрабатываться указанным аддоном.

---

## 23. Аргументы с пробелами

Аргументы, содержащие пробелы, должны быть записаны в кавычках, чтобы терминал обрабатывал их как единый аргумент.

Пример:

`rtg image "C:\Users\User\Downloads\мой образ.png" "C:\Users\User\Downloads\выход.json"`

Полный путь должен быть получен как единый аргумент.

---

## 24. Аргументы аддона должны сохраняться

RtG-CLI не должен модифицировать, удалять или переинтерпретировать аргументы, предназначенные для аддона, если только явное системное правило не указывает иное.

Аргументы должны передаваться аддону в том порядке, в котором они были предоставлены пользователем.

---

## 25. Полные примеры

Команда аддона:

`rtg image`

Помощь:

`rtg help image`

Помощь на английском:

`rtg help image -en`

Запрос языков:

`rtg help image -lang`

Версия CLI:

`rtg --version`

Помощь CLI:

`rtg --help`

Опция, специфичная для аддона:

`rtg image --width 128`

Опция, специфичная для аддона, со значением:

`rtg image --output file.json`

Комбинация:

`rtg image image.png --output output.json`

В этом примере:

* `image` идентифицирует аддон.
* `image.png` — аргумент аддона.
* `--output` — опция аддона.
* `output.json` — значение этой опции.
* Ни один из этих аргументов не должен интерпретироваться как системная опция.

---

## 26. Язык текста запуска

`rtg -language <язык>` выбирает язык текста запуска, отображаемого RtG-CLI.

Язык должен существовать внутри `void-language`.

Пример:

`rtg -language ru`

отображает текст, определённый в:

`void-language.ru`

Если `-language` не указан, RtG-CLI использует `void`.

Если запрошенный язык недоступен, RtG-CLI должен сообщить, что язык недоступен.
