# RtG-CLI コマンドルール

## 1. 一般構造

RtG-CLI コマンドは、メインコマンドとオプションの引数で構成されます。
一般的な形式：

`rtg <コマンド> [<引数>]`

`rtg` の後の最初の引数が、実行されるコマンドまたはアドオンを決定します。

例：

`rtg image`

`rtg preview`

`rtg help image`

---

## 2. 登録済みコマンド

メインコマンドは RtG-CLI 設定に登録されている必要があります。
コマンドは内部キーで識別されます。

例：

`image`

`image` キーは、ユーザーに表示される名前に関係なく、対応するアドオンを識別します。
例：

`image` → `RtG Image`

`preview` → `RtG Preview`

表示名はコマンド識別子として使用してはいけません。

---

## 3. RtG-CLI コマンドとアドオンコマンド

RtG-CLI とアドオンは、それぞれ独自のコマンドと引数を持つことができます。

アドオンが識別される前は、コマンドと引数は RtG-CLI に属します。
アドオンが識別された後は、プレフィックスによって各引数の所有者が決まります：

- ハイフンなし (`-`) → アドオンに属する。
- 二重ハイフン (`--`) → アドオンに属する。
- 単一ハイフン (`-`) → RtG-CLI に属する。

例：

`rtg image convert`

- `image` → アドオン。
- `convert` → アドオンコマンド。

例：

`rtg image --width 128`

- `image` → アドオン。
- `--width` → アドオン引数。
- `128` → アドオン引数の値。

例：

`rtg image -lang`

- `image` → アドオン。
- `-lang` → RtG-CLI 引数。

---

## 4. システム引数

アドオンが識別される前、RtG-CLI は独自の構文ルールを使用します。
長いシステムオプションは二重ハイフンを使用：

`rtg --version`
`rtg --help`

システム略称は単一ハイフンを使用：

`rtg -v`
`rtg -h`
`rtg -l`

アドオンが識別された後、単一ハイフン (`-`) で始まるオプションは RtG-CLI に属します。

例：

`rtg image -lang`
`rtg image -en`

---

## 5. アドオン識別前後の引数

RtG-CLI の引数は、アドオンの識別前か後かによって意味が異なる場合があります。

アドオン識別前は、引数は RtG-CLI に属します。

例：

`rtg --lang`

RtG-CLI で利用可能な言語を表示します。

アドオン識別後、引数はアドオンに確立された所有権ルールに従って解釈されます。

例：

`rtg image -lang`

`image` アドオンで利用可能な言語を照会します。

このように、引数の位置がそのコンテキストを決定し、グローバルな RtG-CLI 引数とアドオン識別後に使用される引数の混同を防ぎます。

---

## 6. システム引数の位置

システム引数は、その引数が依存するコマンドまたはアドオンの前に出現してはなりません。

正しい例：

`rtg help image -en`

間違った例：

`rtg help -en image`

これら 2 つの例では、システムコマンド `help` はこの構造を使用するため、2 番目の例は間違っています：
`help <target> <options>`

位置は、どのコマンドが引数を受け取るかを明確に決定しなければなりません。

---

## 7. アドオンコマンドと引数

コマンドは個別のターミナル引数として記述されます。
コマンドは引用符で囲まれていない限りスペースを含んではいけません。

以降の引数は、アドオンの独自のインターフェースに従って使用されます。

例：

`rtg image convert image`

は次のように解釈できます：

- `image` → アドオン
- `convert` → アドオンコマンド
- `image` → コマンド引数

---

## 8. アドオンコマンドでのハイフン使用

アドオン識別後：

- ハイフンなしの引数はアドオンに属する。
- 2 つ以上のハイフン (`--`) の引数はアドオンに属する。
- 単一ハイフン (`-`) の引数は RtG-CLI に属する。

例：

`rtg image convert`
`convert` → アドオン。

`rtg image --width 128`
`--width` → アドオン。

`rtg image -lang`
`-lang` → RtG-CLI。

---

## 9. アドオンコマンドインターフェース

アドオン固有のコマンドは、アドオンプログラム自体によって定義されます。
RtG-CLI は、アドオン設定の `program commands` プロパティを通じてコマンドインターフェースを特定します。

このプロパティには、プログラムのコマンドインターフェースを提供するファイルへのパスが含まれます。

例：

```json
"program commands": [
    "../tools/RtG Image/commands.py"
]
```

RtG-CLI はこのインターフェースを使用して、アドオンで利用可能なコマンドを検出または実行できますが、その内部コマンドの意味を想定または変更してはいけません。

アドオンは、RtG-CLI コマンドとして直接登録されていない追加コマンドを定義できます。

プログラムの内部実装はアドオン間で異なる場合がありますが、RtG-CLI ルールと互換性のあるインターフェースを提供する限り問題ありません。

---

## 10. 言語

アドオンで利用可能な言語は、その設定で定義されます。

例：

`lang: ["es", "en"]`

翻訳テキストは、対応する言語コードで識別されます。

例：

`content.ja`
`content.en`

RtG-CLI で使用される言語セレクタは、システム引数と見なされます。

例：

`rtg help image -en`

---

## 11. デフォルト言語

`-<言語>` が指定されていない場合、RtG-CLI は `rules` で定義された最初の言語を使用します。
`-<言語>` が指定されている場合、RtG-CLI はその言語が利用可能であれば使用します。

`assets.json` の `rules` オブジェクトで定義された最初の言語が、ルールのデフォルト言語です。

ユーザーが言語を指定せずにルールを要求した場合、RtG-CLI はその最初の言語を使用しなければなりません。

例：

```json
"rules": {
    "es": "./rules.es.md",
    "en": "./rules.en.md"
}
```

この場合：

`rtg -r`
および
`rtg --rules`

は、最初に定義されている言語が `es` であるため、ルールをスペイン語で表示します。
別の言語を要求するには、対応するセレクタを使用します：

`rtg -r -en`

`rules` 内の言語の順序は、どの言語がデフォルトかのみを決定し、利用可能な言語を変更しません。

このルールは、以下のような他の言語セレクタにも適用されます：

`rtg help image -es`

---

## 12. 言語はコマンドを変更しない

言語を変更すると、RtG-CLI が表示するテキストのみが変更されます。
内部コマンド名は変更されません。

例：

`rtg help image -es`

および

`rtg help image -en`

は依然として同じコマンドを参照します：

`image`

---

## 13. ヘルプ

一般的なヘルプは以下で取得：

`rtg help`

特定コマンドのヘルプは以下で取得：

`rtg help <コマンド>`

特定言語でヘルプを要求：

`rtg help <コマンド> -<言語>`

例：

`rtg help image -en`

---

## 14. 言語クエリ

アドオンで利用可能な言語は以下で照会：

`rtg help <コマンド> -lang`

例：

`rtg help image -lang`

このオプションは RtG-CLI に属し、アドオンには属しません。

---

## 15. アドオンはシステムルールを変更してはならない

アドオンは独自のコマンドと引数を定義できますが、RtG-CLI で予約されている引数の意味を再定義してはいけません。

例えば、アドオンは `-h` を使用してシステムヘルプに別の意味を与えてはいけません。
RtG-CLI で予約されている名前はアドオンコマンドより優先されます。
RtG-CLI で予約されているコマンドとオプションは、CLI インターフェースで明示的に定義される必要があります。
アドオンは予約済みオプションの動作を再定義できません。

---

## 16. 識別子と名前の分離

アドオンの内部キーは識別に使用されます。
アドオン名は説明情報またはユーザー表示のみに使用されます。

例：

`image` → 内部識別子

`RtG Image` → 表示名

表示名がコマンドとして使用できると想定してはいけません。

---

## 17. コマンドは決定的でなければならない

RtG-CLI は、プログラムの説明名に依存せず、引数がシステムかアドオンかを判断できなければなりません。

解釈はコマンド構造とルールに基づかなければなりません。

例：

`rtg help image -en`

は常に同じように解釈されなければなりません：

`rtg` → CLI

`help` → CLI コマンド

`image` → アドオン

`-en` → CLI オプション

---

## 18. 未知の引数

アドオン識別後、RtG-CLI はプレフィックスに従って各引数の所有権を決定しなければなりません。

* ハイフンなしの引数はアドオンに属する。
* 2 つ以上のハイフン (`--`) の引数はアドオンに属する。
* 単一ハイフン (`-`) の引数は RtG-CLI に属する。

RtG-CLI が未知のシステム引数を受け取った場合、そのオプションが存在しないことを報告しなければなりません。

アドオン引数は、RtG-CLI がその意味を解釈しようとせずにアドオンに渡さなければなりません。

---

## 19. 登録されていないコマンドを想定しない

RtG-CLI は、関連するフォルダ、ファイル、またはプログラムが存在するだけでコマンドを有効と見なしてはいけません。

コマンドは対応する設定で定義されていなければなりません。

---

## 20. 互換性

アドオンは RtG-CLI 構文ルールに従って正しく統合しなければなりません。
アドオンの内部実装は完全に異なる場合がありますが、そのコマンドインターフェースは RtG-CLI で確立されたルールに従わなければなりません。

---

## 21. 優先ルール

アドオン識別後、単一ハイフン (`-`) は RtG-CLI 用に予約されます。
アドオンは単一ハイフンで始まる引数を使用できません。
2 つ以上のハイフン (`--`) で始まるか、ハイフンで始まらない引数はアドオンに属します。

---

## 22. アドオン引数

アドオンが識別された後、RtG-CLI はアドオン固有の引数の意味を想定してはいけません。

アドオンに属する引数は、アドオンプログラムに渡されて処理されなければなりません。

例：

`rtg image --width 128`

RtG-CLI は `image` をアドオンとして識別します。

`--width 128` は RtG Image インターフェースに対応し、当該アドオンで処理されなければなりません。

---

## 23. スペースを含む引数

スペースを含む引数は、ターミナルが単一引数として扱えるよう引用符で囲む必要があります。

例：

`rtg image "C:\Users\User\Downloads\私の画像.png" "C:\Users\User\Downloads\出力.json"`

完全なパスは単一引数として受信されなければなりません。

---

## 24. アドオン引数は保持されなければならない

明示的なシステムルールがない限り、RtG-CLI はアドオン宛ての引数を変更、削除、再解釈してはいけません。

引数はユーザーが提供した順序でアドオンに渡されなければなりません。

---

## 25. 完全な例

アドオンコマンド：

`rtg image`

ヘルプ：

`rtg help image`

英語ヘルプ：

`rtg help image -en`

言語照会：

`rtg help image -lang`

CLI バージョン：

`rtg --version`

CLI ヘルプ：

`rtg --help`

アドオン固有オプション：

`rtg image --width 128`

値付きアドオン固有オプション：

`rtg image --output file.json`

組み合わせ：

`rtg image image.png --output output.json`

この例では：

* `image` がアドオンを識別。
* `image.png` はアドオン引数。
* `--output` はアドオンオプション。
* `output.json` はそのオプションの値。
* これらの引数のいずれもシステムオプションとして解釈されない。

---

## 26. 起動テキスト言語

`rtg -language <言語>` は RtG-CLI が表示する起動テキストの言語を選択します。

言語は `void-language` 内に存在しなければなりません。

例：

`rtg -language ja`

は以下で定義されるテキストを表示：

`void-language.ja`

`-language` が指定されていない場合、RtG-CLI は `void` を使用。

要求された言語が利用できない場合、RtG-CLI はその言語が利用できないことを報告しなければなりません。
