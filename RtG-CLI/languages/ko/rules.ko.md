# RtG-CLI 명령어 규칙

## 1. 일반 구조

RtG-CLI 명령어는 메인 명령어와 선택적 인수로 구성됩니다.
일반 형식:

`rtg <명령어> [<인수>]`

`rtg` 뒤의 첫 번째 인수가 실행될 명령어 또는 애드온을 결정합니다.

예시:

`rtg image`

`rtg preview`

`rtg help image`

---

## 2. 등록된 명령어

메인 명령어는 RtG-CLI 구성에 등록되어야 합니다.
명령어는 내부 키로 식별됩니다.

예시:

`image`

`image` 키는 사용자에게 표시되는 이름과 관계없이 해당 애드온을 식별합니다.
예시:

`image` → `RtG Image`

`preview` → `RtG Preview`

표시된 이름은 명령어 식별자로 사용해서는 안 됩니다.

---

## 3. RtG-CLI 명령어와 애드온 명령어

RtG-CLI와 애드온은 각각 고유한 명령어와 인수를 가질 수 있습니다.

애드온이 식별되기 전에는 명령어와 인수가 RtG-CLI에 속합니다.
애드온이 식별된 후에는 접두사가 각 인수의 소유자를 결정합니다:

- 하이픈 없음 (`-`) → 애드온에 속함.
- 이중 하이픈 (`--`) → 애드온에 속함.
- 단일 하이픈 (`-`) → RtG-CLI에 속함.

예시:

`rtg image convert`

- `image` → 애드온.
- `convert` → 애드온 명령어.

예시:

`rtg image --width 128`

- `image` → 애드온.
- `--width` → 애드온 인수.
- `128` → 애드온 인수의 값.

예시:

`rtg image -lang`

- `image` → 애드온.
- `-lang` → RtG-CLI 인수.

---

## 4. 시스템 인수

애드온이 식별되기 전, RtG-CLI는 자체 구문 규칙을 사용합니다.
긴 시스템 옵션은 이중 하이픈 사용:

`rtg --version`
`rtg --help`

시스템 약어는 단일 하이픈 사용:

`rtg -v`
`rtg -h`
`rtg -l`

애드온이 식별된 후, 단일 하이픈 (`-`)으로 시작하는 옵션은 RtG-CLI에 속합니다.

예시:

`rtg image -lang`
`rtg image -en`

---

## 5. 애드온 식별 전후의 인수

RtG-CLI 인수는 애드온 식별 전후에 따라 다른 의미를 가질 수 있습니다.

애드온 식별 전에는 인수가 RtG-CLI에 속합니다.

예시:

`rtg --lang`

RtG-CLI에서 사용 가능한 언어를 표시합니다.

애드온 식별 후, 인수는 애드온에 확립된 소유권 규칙에 따라 해석됩니다.

예시:

`rtg image -lang`

`image` 애드온에서 사용 가능한 언어를 조회합니다.

이렇게 인수의 위치는 컨텍스트를 결정하고, 전역 RtG-CLI 인수가 애드온 식별 후 사용되는 인수와 혼동되는 것을 방지합니다.

---

## 6. 시스템 인수의 위치

시스템 인수는 해당 인수가 의존하는 명령어 또는 애드온 앞에 나타나서는 안 됩니다.

올바른 예시:

`rtg help image -en`

잘못된 예시:

`rtg help -en image`

이 두 예시에서 시스템 명령어 `help`는 이 구조를 사용하므로 두 번째 예시는 잘못되었습니다:
`help <target> <options>`

위치는 어느 명령어가 인수를 받는지 명확히 결정해야 합니다.

---

## 7. 애드온 명령어와 인수

명령어는 개별 터미널 인수로 작성됩니다.
명령어는 따옴표로 묶이지 않는 한 공백을 포함할 수 없습니다.

이후 인수는 애드온의 자체 인터페이스에 따라 사용될 수 있습니다.

예시:

`rtg image convert image`

는 다음과 같이 해석될 수 있습니다:

- `image` → 애드온
- `convert` → 애드온 명령어
- `image` → 명령어 인수

---

## 8. 애드온 명령어에서 하이픈 사용

애드온 식별 후:

- 하이픈 없는 인수는 애드온에 속함.
- 이중 하이픈 이상 (`--`) 인수는 애드온에 속함.
- 단일 하이픈 (`-`) 인수는 RtG-CLI에 속함.

예시:

`rtg image convert`
`convert` → 애드온.

`rtg image --width 128`
`--width` → 애드온.

`rtg image -lang`
`-lang` → RtG-CLI.

---

## 9. 애드온 명령어 인터페이스

애드온별 명령어는 애드온 프로그램 자체에서 정의됩니다.
RtG-CLI는 애드온 구성의 `program commands` 속성을 통해 명령어 인터페이스를 찾습니다.

이 속성에는 프로그램의 명령어 인터페이스를 제공하는 파일 경로가 포함됩니다.

예시:

```json
"program commands": [
    "../tools/RtG Image/commands.py"
]
```

RtG-CLI는 이 인터페이스를 사용하여 애드온에서 사용 가능한 명령어를 검색하거나 실행할 수 있지만, 내부 명령어의 의미를 가정하거나 수정해서는 안 됩니다.

애드온은 RtG-CLI 명령어로 직접 등록되지 않은 추가 명령어를 정의할 수 있습니다.

프로그램의 내부 구현은 애드온마다 다를 수 있으며, RtG-CLI 규칙과 호환되는 인터페이스를 제공하는 한 문제가 없습니다.

---

## 10. 언어

애드온에서 사용 가능한 언어는 구성을 통해 정의됩니다.

예시:

`lang: ["es", "en"]`

번역된 텍스트는 해당 언어 코드로 식별됩니다.

예시:

`content.ko`
`content.en`

RtG-CLI에서 사용하는 언어 선택자는 시스템 인수로 간주되어야 합니다.

예시:

`rtg help image -en`

---

## 11. 기본 언어

`-<언어>`가 지정되지 않은 경우, RtG-CLI는 `rules`에 정의된 첫 번째 언어를 사용합니다.
`-<언어>`가 지정된 경우, RtG-CLI는 해당 언어가 사용 가능한 경우 사용합니다.

`assets.json`의 `rules` 객체에서 정의된 첫 번째 언어가 규칙의 기본 언어입니다.

사용자가 언어 없이 규칙을 요청하면 RtG-CLI는 해당 첫 번째 언어를 사용해야 합니다.

예시:

```json
"rules": {
    "es": "./rules.es.md",
    "en": "./rules.en.md"
}
```

이 경우:

`rtg -r`
및
`rtg --rules`

는 `es`가 첫 번째로 정의된 언어이므로 스페인어로 규칙을 표시합니다.
다른 언어를 요청하려면 해당 선택자를 사용해야 합니다:

`rtg -r -en`

`rules` 내 언어 순서는 기본 언어만 결정하며 사용 가능한 언어를 변경하지 않습니다.

이 규칙은 다음과 같은 다른 언어 선택자에도 적용됩니다:

`rtg help image -es`

---

## 12. 언어는 명령어를 변경하지 않음

언어 변경은 RtG-CLI가 표시하는 텍스트만 수정합니다.
내부 명령어 이름은 변경되지 않습니다.

예시:

`rtg help image -es`

와

`rtg help image -en`

은 여전히 같은 명령어를 참조합니다:

`image`

---

## 13. 도움말

일반 도움말은 다음으로 얻습니다:

`rtg help`

특정 명령어 도움말은 다음으로 얻습니다:

`rtg help <명령어>`

특정 언어로 도움말 요청:

`rtg help <명령어> -<언어>`

예시:

`rtg help image -en`

---

## 14. 언어 조회

애드온에서 사용 가능한 언어는 다음으로 조회:

`rtg help <명령어> -lang`

예시:

`rtg help image -lang`

이 옵션은 RtG-CLI에 속하며 애드온에 속하지 않습니다.

---

## 15. 애드온은 시스템 규칙을 수정하지 않아야 함

애드온은 자체 명령어와 인수를 정의할 수 있지만, RtG-CLI에서 예약한 인수의 의미를 재정의할 수 없습니다.

예를 들어, 애드온은 `-h`를 사용하여 시스템 도움말에 다른 의미를 부여해서는 안 됩니다.
RtG-CLI에서 예약된 이름은 애드온 명령어보다 우선합니다.
RtG-CLI에서 예약된 명령어와 옵션은 CLI 인터페이스에서 명시적으로 정의되어야 합니다.
애드온은 예약된 옵션의 동작을 재정의할 수 없습니다.

---

## 16. 식별자와 이름의 분리

애드온의 내부 키는 식별에 사용됩니다.
애드온 이름은 설명 정보 또는 사용자 표시용으로만 사용됩니다.

예시:

`image` → 내부 식별자

`RtG Image` → 표시 이름

표시 이름이 명령어로 사용될 수 있다고 가정하지 마세요.

---

## 17. 명령어는 결정적이어야 함

RtG-CLI는 프로그램의 설명 이름에 의존하지 않고 인수가 시스템인지 애드온인지 결정할 수 있어야 합니다.

해석은 명령어 구조와 규칙에 기반해야 합니다.

예시:

`rtg help image -en`

은 항상 동일하게 해석되어야 합니다:

`rtg` → CLI

`help` → CLI 명령어

`image` → 애드온

`-en` → CLI 옵션

---

## 18. 알 수 없는 인수

애드온 식별 후, RtG-CLI는 접두사에 따라 각 인수의 소유권을 결정해야 합니다.

* 하이픈 없는 인수는 애드온에 속함.
* 이중 하이픈 이상 (`--`) 인수는 애드온에 속함.
* 단일 하이픈 (`-`) 인수는 RtG-CLI에 속함.

RtG-CLI가 알 수 없는 시스템 인수를 받으면 해당 옵션이 존재하지 않음을 보고해야 합니다.

애드온 인수는 RtG-CLI가 그 의미를 해석하려 하지 않고 애드온에 전달되어야 합니다.

---

## 19. 등록되지 않은 명령어 가정하지 않음

RtG-CLI는 관련 폴더, 파일, 프로그램이 존재한다는 이유만으로 명령어를 유효하다고 간주해서는 안 됩니다.

명령어는 해당 구성에 정의되어야 합니다.

---

## 20. 호환성

애드온은 RtG-CLI 구문 규칙을 따라야 올바르게 통합됩니다.
애드온은 완전히 다른 내부 구현을 가질 수 있지만, 명령어 인터페이스는 RtG-CLI에서 확립된 규칙을 따라야 합니다.

---

## 21. 우선순위 규칙

애드온 식별 후, 단일 하이픈 (`-`)은 RtG-CLI용으로 예약됩니다.
애드온은 단일 하이픈으로 시작하는 인수를 사용할 수 없습니다.
이중 하이픈 (`--`)으로 시작하거나 하이픈으로 시작하지 않는 인수는 애드온에 속합니다.

---

## 22. 애드온 인수

애드온이 식별되면 RtG-CLI는 애드온별 인수의 의미를 가정하지 않아야 합니다.

애드온에 속하는 인수는 애드온 프로그램에 전달되어 처리되어야 합니다.

예시:

`rtg image --width 128`

RtG-CLI는 `image`를 애드온으로 식별합니다.

`--width 128`은 RtG Image 인터페이스에 해당하며 해당 애드온에서 처리되어야 합니다.

---

## 23. 공백이 있는 인수

공백이 포함된 인수는 터미널이 단일 인수로 처리하도록 따옴표로 묶어야 합니다.

예시:

`rtg image "C:\Users\User\Downloads\내 이미지.png" "C:\Users\User\Downloads\출력.json"`

전체 경로는 단일 인수로 수신되어야 합니다.

---

## 24. 애드온 인수는 보존되어야 함

명시적 시스템 규칙이 없는 한, RtG-CLI는 애드온 대상 인수를 수정, 제거, 재해석하지 않아야 합니다.

인수는 사용자가 제공한 순서대로 애드온에 전달되어야 합니다.

---

## 25. 전체 예시

애드온 명령어:

`rtg image`

도움말:

`rtg help image`

영어 도움말:

`rtg help image -en`

언어 조회:

`rtg help image -lang`

CLI 버전:

`rtg --version`

CLI 도움말:

`rtg --help`

애드온 전용 옵션:

`rtg image --width 128`

값이 있는 애드온 전용 옵션:

`rtg image --output file.json`

조합:

`rtg image image.png --output output.json`

이 예시에서:

* `image`가 애드온을 식별.
* `image.png`는 애드온 인수.
* `--output`은 애드온 옵션.
* `output.json`은 해당 옵션의 값.
* 이 인수 중 어느 것도 시스템 옵션으로 해석되지 않아야 함.

---

## 26. 시작 텍스트 언어

`rtg -language <언어>`는 RtG-CLI가 표시하는 시작 텍스트의 언어를 선택합니다.

언어는 `void-language` 내에 존재해야 합니다.

예시:

`rtg -language ko`

는 다음에 정의된 텍스트를 표시:

`void-language.ko`

`-language`가 지정되지 않은 경우, RtG-CLI는 `void`를 사용합니다.

요청한 언어가 사용 불가능한 경우, RtG-CLI는 해당 언어가 사용 불가능함을 보고해야 합니다.
